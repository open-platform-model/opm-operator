## Context

`docs/site/reference/operator-resources.md` is a stub: front matter, a planning comment and an authored "See also" section. `opmodel.dev` assembles every repository's `docs/site/` into one site and fails its build on a page-dialect error or a broken link. The four CRDs are controller-gen output from `api/v1alpha1`, so their descriptions are the types' Go doc comments. Reconcile phase impact: none (Source, Render, Apply, Prune and Status are untouched); this is documentation tooling.

## Goals / Non-Goals

**Goals:**

- One generated entry per kind, every part derived from a file in this repository.
- A stale page fails CI, and an example on the page is one the API server admits.
- The page passes the site's dialect lint and build.

**Non-Goals:**

- Status condition types and reasons. They are not declared in the CRDs, and which reconciler sets which reason is not derivable from a constant; the authored "Operator conditions" page owns them.
- Rewriting field doc comments for site readers beyond the four kind summaries. Several fields carry no doc comment, and some comments are written for maintainers; both show on the page as they are.
- Fixing the samples. They validate; one is stale in content (below), not in schema.

## Decisions

### D1. Sources: the committed CRDs, not the Go types

`hack/crdref` reads `config/crd/bases/*.yaml`, which already resolve every embedded and referenced type (Flux references, `metav1.Condition`) into one schema with its constraints. Reading the Go types would mean re-implementing controller-gen's marker handling. `task dev:docs:reference` runs `dev:manifests` first, so a types edit flows through.

### D2. Entry shape

For each CRD, ordered by kind:

| Part | Source | Omitted when |
| --- | --- | --- |
| Summary | First sentence of the root schema description | never (every kind has a doc comment) |
| At a glance | `spec.group`, version name, `names`, `scope`, subresources; printer columns as a second table | categories, subresources or printer columns absent |
| Spec, Status | One row per property under `spec` and `status`, recursing into objects (`a.b`), array items (`a[].b`) and map values (`a.<key>.b`); columns field, type, required, description, and default only when a row has one | the section has no properties |
| Example | First document of the kind in `config/samples/<group>_<version>_<kind>.yaml`, re-encoded without comments and without kubebuilder's two scaffold labels | no such file or document |
| Notes | The rest of the root description, paragraph by paragraph | nothing after the first sentence |
| Served by | The `internal/controller` function whose builder chain holds `For(&<pkg>.<Kind>{})` and one `Named("<name>")` | no such function |
| Enforcement | Every schema rule: root CEL rules, `required`, `minLength`, `maxLength`, `pattern`, `enum`, bounds, item and property counts, list-map keys and set uniqueness, field CEL rules; each tagged "API server" | no rule |

`status.conditions` is recognised by shape (a list keyed by `type` whose items carry the five required `metav1.Condition` fields) and shown as one `[]Condition` row, without its standard Kubernetes rules.

### D3. Text from doc comments

Paragraphs fold onto one line; a table cell takes the whole description on one line. Outside backtick spans, Markdown and HTML metacharacters are escaped, because the site renders raw HTML (`unsafe = true`) and `<namespace>` would otherwise become a tag. A decision citation such as `0015:D3/D16` becomes a link to `/enhancements/0015/decisions/`, the only enhancement link form the dialect allows below an entry. The generator refuses a block that would hold a shortcode opener, a raw `href=`/`src=` or an image, which the site lint rejects.

### D4. Markers and the check

The block sits between two HTML comment lines, `BEGIN GENERATED by hack/crdref ...` and `END GENERATED by hack/crdref`, each once, in order; the minifier drops comments from the published page. `-check` regenerates in memory and fails naming the page and the task to run. Output is deterministic: properties, rules and kinds are sorted, and samples are re-encoded with sorted keys.

### D5. Samples proven by the API server

`TestSamplesAdmittedByTheCRDs` starts envtest with the committed CRDs and dry-run creates every `opmodel.dev` object in every `config/samples` file with `fieldValidation=Strict`, so a field the schema dropped fails instead of being pruned. The generator does not validate on its own: the API server is the authority the page names.

## Research & Decisions

### Samples

**Context**: The brief allows an example only when the sample is current with the schema.
**Explored**: Ran the new spec against all four `opmodel.dev` samples, and once with an unknown `spec.bogusField` added to the Platform sample (it failed with `strict decoding error: unknown field "spec.bogusField"`, as intended).
**Decision**: ModuleInstance, ModulePackage and Platform get their examples; TransformerRegistration has no sample and no example.
**Rationale**: All four sample objects are admitted. `opmodel.dev_v1alpha1_moduleinstance_jellyfin.yaml` is admitted but names `opmodel.dev/modules/jellyfin@v1`, which the `modules` repository's `main` no longer carries; the generator does not use it (only the canonical file name is read), and it is left for its own change.

### Kind summaries

**Context**: kubebuilder's scaffold opens three kind doc comments with "X is the Schema for the xs API", which says nothing as a summary.
**Decision**: Rewrite the first sentence of each kind's doc comment from facts the existing comments already state (the ModulePackage spec comment, the Platform spec comment, the TransformerRegistration spec comment, the `OwnerCLI` comment).
**Rationale**: The rule is that a generated entry states what its source proves; the fix for a poor summary is the source.

### One page

**Context**: Four kinds on one page is about 450 lines of Markdown, most of it two status tables that kubebuilder-style status types fill with undocumented counters and digests.
**Decision**: Keep one page at `/docs/reference/operator-resources/`; each kind is an `h2` with a stable anchor (`#moduleinstance`, `#platform`, ...).
**Rationale**: The built page reads as a list of four entries with a table of contents; splitting would add four pages and a section index for no gain, and other pages already link this URL.
