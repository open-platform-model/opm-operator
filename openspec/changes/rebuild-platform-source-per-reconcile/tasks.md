# Tasks: rebuild-platform-source-per-reconcile

There are two sections, following design.md. Section 1 is a spike, because design.md has one unverified assumption: whether the flaky front can route the catalog's traffic (longest-prefix mapping, repository rewrite, GHCR token flow). It lands the harness and the companion spec, which pass before the fix. Section 2 lands the fix together with the reconcile-level regression spec, which only passes once the fix is in.

## 1. Flaky registry front and the upstream-cause spec (test/integration/reconcile)

- [ ] 1.1 Add the `flakyFront` helper as a test file in `test/integration/reconcile`. It is an `httptest.Server` with a down/forwarding switch. While down it answers `503`. While forwarding it reverse-proxies to the host that `modconfig.NewResolver(...).ResolveToLocation` resolves for the catalog under the suite's `CUE_REGISTRY`, rewrites the repository prefix to the live `Repository`, and counts forwarded requests. Also add a constructor for the reconciler mapping: the live mapping plus one longest-prefix entry that sends the catalog's module path to `127.0.0.1:<port>+insecure`. Move the empty-`CUE_CACHE_DIR` setup and teardown out of `platform_recovery_test.go` into a shared helper, so that spec and the new ones use one implementation (`os.MkdirTemp`, walk back to writable, then remove; restore the variable in `DeferCleanup`). Verify: `go vet ./test/integration/...` passes.
- [ ] 1.2 Add the companion spec "a reused module-file source keeps serving a registry failure". It gates like `liveBuildKernelOrSkip` and uses an empty `CUE_CACHE_DIR`. After the front switches to forwarding, the same source fails again and a new source succeeds, with the front's forwarded count above zero. Verify: `go test ./test/integration/reconcile/... -ginkgo.focus="reused module-file source"` passes against the suite's registry. If the GHCR route cannot be made to work, apply the fallback in design.md § Risks (run only when the upstream resolves `Insecure`, otherwise skip with a named reason) and confirm the spec passes under `task dev:test:seeded`.
