# operator-resource-reference Specification

## Purpose
The operator resource reference page at `/docs/reference/operator-resources/`: generated into the docs bundle by docs-kit from the CRDs and samples and completed by the committed intro, the test that keeps each entry's controller name true, and the check that every sample is admitted by the CRDs.

## Requirements

### Requirement: The resource reference is generated into the docs bundle

The operator resource reference SHALL be generated by docs-kit's `crd` extractor from `config/crd/bases` and `config/samples` when the operator's docs bundle is built, at `reference/operator-resources.md` (`/docs/reference/operator-resources/`), one entry per kind in the order ModuleInstance, ModulePackage, Platform, TransformerRegistration. The committed `docs/site/reference/operator-resources.md` SHALL hold only authored front matter and intro, with no marker lines and no `## <Kind>` heading, and the bundle SHALL show that intro first and the generated entries after it.

#### Scenario: The authored intro completes the page

- **WHEN** the bundle is built
- **THEN** `reference/operator-resources.md` starts with the committed front matter (`weight: 7`) and intro, followed by the `## ModuleInstance` entry

#### Scenario: A generated heading in the authored page is refused

- **WHEN** a contributor adds `## ModuleInstance` to the committed page
- **THEN** `task docs:bundle:check` fails, naming the page and the heading

### Requirement: The controller each entry names is the controller that reconciles the kind

`docs-kit.cue`'s `reconciledBy` SHALL map each of the four kinds to the `Named(...)` value of the controller whose builder in `internal/controller` calls `For(&v1alpha1.<Kind>{})`. A test run by `task dev:test` SHALL fail, naming the kind, when the two differ.

#### Scenario: A renamed controller fails the test

- **WHEN** a contributor changes `Named("platform")` to `Named("platform-reconciler")` and leaves `docs-kit.cue` as it was
- **THEN** the test fails, naming Platform and both names

#### Scenario: Agreeing names pass

- **WHEN** `docs-kit.cue` and the controllers agree
- **THEN** the test passes

### Requirement: Every sample is admitted by the CRDs

The `crdvalidation` integration tier SHALL dry-run create every `opmodel.dev` object in every `config/samples` file against the committed CRDs with strict field validation and fail on any rejection, so an example the reference shows is one the API server admits.

#### Scenario: Sample carries a field the schema does not have

- **WHEN** a sample in `config/samples` holds a field its CRD does not define
- **THEN** `TestSamplesAdmittedByTheCRDs` fails with the API server's unknown-field error for that sample
